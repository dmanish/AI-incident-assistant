3. Three-Tier Semantic Routing System NEW

Replaces keyword matching with intelligent semantic understanding of user intent.

1
Tier 1: Override Rules (Config-Based)

Location: config/routing_rules.yaml

Matcher: app/agent/rule_matcher.py

Deterministic rules that override semantic routing for high-precision cases.

Rule Categories (7 types):

Category Example Pattern Priority Route
cve_queries regex: CVE-\d{4}-\d+ 10 web_search only
ip_reputation keyword: "IP reputation", "malicious IP" 9 web_search only
domain_analysis keyword: "suspicious domain" 9 web_search only
log_queries keyword: "failed login", "auth logs" 8 logs only
policy_playbook keyword: "policy", "playbook", "procedure" 7 rag only
combined_analysis keyword: "correlate", "analyze together" 6 rag + logs + web
generic_security keyword: "security", "incident" 5 rag + logs 
# Example rule in YAML:
cve_queries:
  priority: 10
  patterns:
    - type: regex
      value: 'CVE-\d{4}-\d+'
      case_sensitive: false
  route:
    use_rag: false
    use_logs: false
    use_web_search: true
  description: "CVE lookup requires external API"
2
Tier 2: Semantic Vector Search

Location: semantic_router.py:64-150

Database: data/routing_db/ (ChromaDB collection)

Training Data: data/routing/seed_examples.json (40+ examples)

How It Works:

  1. User query is embedded using all-MiniLM-L6-v2 (384-dim)
  2. Query ChromaDB for top-5 most similar routing examples
  3. Calculate confidence score (cosine similarity)
  4. Apply thresholds:
    • High confidence: > 0.7 → use route directly
    • Medium confidence: 0.5-0.7 → aggregate similar routes
    • Low confidence: < 0.5 → fallback to Tier 3
# Example training data structure:
{
  "query": "Show me failed login attempts for user jdoe",
  "category": "log_queries",
  "use_rag": false,
  "use_logs": true,
  "use_web_search": false,
  "reasoning": "Direct log query, no external lookup needed"
}
Configuration: routing_config.py
  • SEMANTIC_SIMILARITY_THRESHOLD = 0.5
  • HIGH_CONFIDENCE_THRESHOLD = 0.7
  • MAX_SEARCH_RESULTS = 5
3
Tier 3: LLM Fallback

Location: semantic_router.py:215-245

When semantic search has low confidence, use LLM to reason about routing.

Fallback Logic:

  • Simple keyword detection for safety
  • Default route: {use_rag: true, use_logs: false, use_web_search: false}
  • Logs analytics via routing_logger.py

Routing Decision Flow

User Query → "What is CVE-2024-1234?"

Step 1 (Override): Check YAML rules
  ✓ Match: cve_queries (priority 10, regex: CVE-\d{4}-\d+)
  → Route: {use_web_search: true, use_rag: false, use_logs: false}
  → Method: "override"
  → Confidence: 1.0

Result: Web search ONLY (skip Tier 2 & 3)
User Query → "How do I respond to a phishing email?"

Step 1 (Override): Check YAML rules
  ✗ No high-priority match

Step 2 (Semantic): Query routing vector DB
  Top result: "What's the procedure for phishing incidents?"
  Similarity: 0.85 (HIGH confidence)
  → Route: {use_rag: true, use_logs: false, use_web_search: false}
  → Method: "semantic"
  → Confidence: 0.85

Result: RAG retrieval (playbook_phishing.md)

True agentic system using LLM function calling APIs for iterative reasoning and autonomous tool execution.

2
Iterative Reasoning Loop

Location: function_calling_agent.py:100-250

Max Iterations: 5 (configurable)

Agent Loop:

for iteration in range(max_iterations):
    # 1. LLM decides which tools to call
    response = llm.chat.completions.create(
        model="gpt-4o-mini",
        messages=conversation_history,
        tools=TOOL_DEFINITIONS,  # search_knowledge_base, search_logs, search_threat_intelligence
        tool_choice="auto"
    )

    # 2. If no tool calls → final answer
    if not response.tool_calls:
        return response.message.content

    # 3. Execute tools in parallel
    tool_results = execute_tools_parallel(response.tool_calls)

    # 4. Add results to conversation
    conversation_history.append(tool_results)

    # 5. Continue loop (LLM sees results, decides next action)
Example 5-Iteration Flow:
  1. Iteration 1: LLM calls search_knowledge_base("phishing")
  2. Iteration 2: LLM calls search_authentication_logs(username="jdoe")
  3. Iteration 3: LLM calls search_threat_intelligence(ioc_type="ip", value="1.2.3.4")
  4. Iteration 4: LLM synthesizes all results
  5. Iteration 5: Returns final answer (no more tool calls)

5. Tool Implementations

Tool 1: search_knowledge_base

Executor: executors_enhanced.py:20-80

  • Queries Chroma vector DB (security_docs collection)
  • Uses sentence-transformers for embeddings
  • Re-ranks with BM25 for keyword relevance
  • Filters by RBAC (role-based document access)
  • Returns top-k chunks with metadata

Tool 2: search_authentication_logs

Executor: executors_enhanced.py:82-150

  • Queries DuckDB over CSV log files
  • Supports filtering by username, date, action
  • Aggregation support (count, unique IPs, etc.)
  • RBAC check (only security/engineering roles)
  • Returns structured DataFrame results

Tool 3: search_threat_intelligence

Executor: executors_enhanced.py:152-220

Web Search: app/utils/web_search.py

  • CVE: NVD API + CISA KEV database
  • IP: DuckDuckGo scraping + optional AbuseIPDB
  • Domain: DuckDuckGo malicious domain check
  • Caching to avoid redundant API calls
  • Returns enriched IOC data

Tool Execution Modes

  • Parallel: Multiple tools run concurrently
  • Sequential: Agent can call tools across iterations
  • Conditional: LLM decides which tools based on context
  • Error Handling: Graceful degradation if tool fails

6. Two-Level RAG System

1
Level 1: Bootstrap & Ingestion

Scripts:

  • scripts/bootstrap.py - Initial data setup
  • scripts/ingest.py - Build RAG vector DB
  • scripts/ingest_routing_examples.py - Build routing vector DB

Chunking Strategy:

  • Chunk Size: 800 word tokens
  • Overlap: 120 tokens (15%)
  • Method: Simple sliding window (can upgrade to semantic chunking)

Embedding Provider:

  • Local (default): all-MiniLM-L6-v2 (384-dim, CPU-friendly)
  • OpenAI (optional): text-embedding-3-small (1536-dim)
2
Level 2: Hybrid Retrieval (Vector + BM25)

Location: executors_enhanced.py:20-80

Hybrid Search Process:

  1. Vector Search: Query Chroma for top-20 semantically similar chunks
  2. BM25 Re-ranking: Apply keyword-based relevance scoring
  3. RBAC Filtering: Remove chunks user's role can't access
  4. Top-K Selection: Return top-5 after re-ranking
# Hybrid retrieval pseudocode
results = chroma.query(query, n_results=20)
corpus = [chunk.text for chunk in results]
bm25 = BM25Okapi(corpus)
scores = bm25.get_scores(query.split())
reranked = sort_by_score(results, scores)
filtered = [r for r in reranked if role_allows_doc(user_role, r.doc_type)]
return filtered[:5]

2. Data Loss Prevention (DLP)

Location: app/security/dlp.py

Applied: Post-LLM, before response to user

Masked Patterns:

  • Emails: user@example.com → [EMAIL_REDACTED]
  • IP Addresses: 192.168.1.1 → [IP_REDACTED]
  • JWTs: eyJhbGc... → [JWT_REDACTED]
  • AWS Keys: AKIA... → [AWS_KEY_REDACTED]
  • High Entropy: Random strings >24 chars → [SECRET_REDACTED]
Entropy Detection: Uses Shannon entropy to detect random tokens (likely secrets)
